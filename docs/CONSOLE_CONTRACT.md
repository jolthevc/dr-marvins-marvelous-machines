# Future GitHub Console Contract v1.0

**Status:** Specified, NOT implemented. This document is the exact interface the future simple browser console should honor.

## Design goal

One compact internal webpage. No authentication console, social scheduling, dashboards, charting, complicated production management or new creative agents. The work starts in a chat and ends with an exportable Instagram package.

**Future primary actions:**

- `Browse Ideas`: read the repo registry, display list and statuses, select one.
- `New ideas`: show copyable entry prompt; optionally later call a connected generation workflow if intentionally built.
- `Create Post`: load validated `.packet.json` for a selected idea.
- `Add Illustration`: user uploads one approved PNG, or uses a copyable art-generation brief elsewhere.
- `Export Carousel`: render and download four PNGs + caption.

## Required source fields

Source of truth is `schemas/post-packet.schema.json` with `schema_version: dmmm_post_v1`. Reject mismatched versions. Every post has:

- Canonical IDs and revision.
- Central invention details and concept disclosure.
- One text-free illustration art brief.
- All four slides' exact copy.
- Caption.
- Optional asset links/status and internal QA notes.

The console renders exact supplied text. No LLM calls are required to create Slides 2 to 4. Changes to copy happen by revising canonical packet upstream, not by silent HTML rewriting.

## Rendering surfaces

**Slide 1:** One supplied machine art PNG + reusable HTML frame, title, hook, fixed lab label, concept marker, footer and `01 / 04`. All typography HTML.

**Slide 2:** HTML-only `A MOST DREADFUL PROBLEM`: short heading + 35 to 70 words + red accent.

**Slide 3:** HTML-only `THE STROKE OF GENIUS`: thesis if present + 3 features. No illustration, thumbnail or inset is required or permitted on this slide. Its design is text and HTML/CSS only.

**Slide 4:** HTML-only `GENIUS OR MADNESS?`: one specific question, GENIUS/MADNESS verdict labels and comment prompt.

All four exactly 1080 x 1350 px, fixed margins, shared `#F2E8D3` paper, dark ink and restrained red. Footer text and page counters are compositor-owned, not generated by image model. Preview at both full-size and 25% mobile approximation.

## Sample UI state machine

`NO_SELECTION -> PACKET_LOADED -> NEEDS_ILLUSTRATION -> PREVIEW_READY -> QA_PASSED -> EXPORTED`

Invalid packet, absent image, unreadable render or missing rights check stay explicitly blocked. Reload should preserve draft selection/assets only when durable persistence is implemented; do not claim recoverability without building storage.

## Art file expectations

- Accept PNG, reasonably high-resolution, with correct legibility; ideally art without words and without background.
- If image has parchment already, use consistent background and fit it without hard edge seams.
- One core asset per post. Reject inaccurate product depiction or art that introduces mechanisms inconsistent with packet.
- Do not simulate crop results. Generate actual previews and final exports before marking RENDERED.
- Remove metadata/identifiers when appropriate; do not expose private uploaded source data.

## Exports

Deliver a folder or ZIP:

```
MM-P0001/
  01-invention.png
  02-problem.png
  03-solution.png
  04-verdict.png
  caption.txt
  manifest.json
```

The manifest contains packet ID/revision, asset hash when obtainable, export size, generation time from actual runtime, and a *real* validation result. No claims of quality checks without execution.

## Save boundary

GitHub: rules, idea registry, finalized JSON packets and text metadata. Art and PNG exports: external storage or user download. Keep only stable references in packet, never fabricate paths. For later GitHub-connected saving, read branch head and reconcile edits rather than overwriting a recent packet or registry.

## Non-goals and expansion discipline

Do not build n8n, a queue, a user account system, artificial engagement analytics, scheduled posting, direct Instagram publishing, AI video, in-console full invention ideation, five-screen wizard, template picker, or dozens of user settings in version 1. The creative system gets its consistency from governance and CSS tokens, not interface complexity.
